Website Management

Site-wide controls: take the site down for maintenance, or post a notice banner for everyone to see.

Security Alerts

Attacks the site detected: injection attempts, attack tools, probing for hidden files, forged logins and password guessing. Each is listed by the attacker's IP address, with whether it came from a member account or looks like a random attack. Webmasters are also emailed (at most once per address every 6 hours).

Staff Activity

Every change made by a webmaster, an admin or the Treasurer: approving or removing accounts, role changes, deletions, restores, site settings, dues, and cave approvals and edits - who did it, when, and from what address.

Data Downloads

Every time cave data leaves the site: each copy of the cave database a browser downloads (one per login), every export (CSV, Excel, GPX, database file, Cave Profile), every map file and every backup. Exports carry an Export ID (on every row of a spreadsheet, and in the file name), so if a file turns up somewhere it shouldn't, paste its Export ID here to see who it was made for.

Maintenance Mode

While maintenance mode is on, visitors see an "under construction" page and every other account is locked out. You (and any admin) can still use the site as usual by going to /portal directly instead of the normal site address - bookmark it now, since the normal login form won't be reachable while this is on.

Schedule a Maintenance Window (optional)

Set a start and end time and maintenance mode turns itself on and back off automatically - you don't need to be online at either moment. This works independently of the toggle above; leave both blank to cancel a scheduled window.

Notification Banner

Shows a thin bar at the very top of every page, for everyone, logged in or not. Web addresses (like https://example.com, www.caves.org or fcs.caves.org/portal) and email addresses (like someone@caves.org) you type automatically become clickable links - no HTML needed.

Read-Only Mode

A lighter option than full maintenance mode: the site stays fully browsable (map, database, statistics all work normally), but members can't submit new cave proposals or add/edit narratives. Admin and webmaster can still write as usual. Use this during a data migration or other change where you want eyes off writes without taking the whole site down.

Large File Uploads/Downloads

Blocks uploading AND viewing/downloading narrative photos and cave map files (GeoTIFFs, shapefiles) site-wide, for every role including admin and webmaster - use this while the server isn't set up to handle large files yet. Submitting and editing cave data, and narratives themselves, keep working normally.

Tab Visibility

Hide a tab from members and admins while a feature in it is broken or still being worked on. Webmasters always keep every tab, marked "hidden", so you can keep working on it. Checked means visible to everyone; unchecked means webmasters only. Account Management and Website Management can't be hidden.

Interactive Map Tools

Hide these parts of the Interactive Map tab from everyone except webmasters (members and admins). Webmasters always see them, marked as hidden. Checked means visible to everyone; unchecked means webmasters only.

Cave Jump Scoreboard

Clears every score from the Cave Jump Top 10 so everyone starts fresh. A backup of the old scores is kept on the server.

Login Security

After this many failed attempts in a row, an account is temporarily locked out (in addition to the site's own IP-based rate limiting). Applies immediately to the next login attempt.

A logged-in account is signed out and blocked if, within 10 minutes, it keeps trying features its role can't use, probes for pages that don't exist, sends hacking-style input, floods the site with requests, or keeps entering the wrong current password. Webmasters are emailed, and can lift it early in Account Management. Webmaster accounts are never restricted.

Backups & Recovery

The site's data (accounts, caves, submissions, narratives and settings) is backed up automatically every day and kept for weeks, so it can be put back in one step if anything is damaged or maliciously changed. Restoring needs your password, saves the current data first (so a restore can itself be undone), and signs everyone out. Photos and cave map files aren't included; Plesk's own backups cover those.

Loading backups...

Keep a downloaded copy somewhere off the server now and then (your computer or cloud storage): it can rebuild the site even if the server's own backups are lost.

Usage Snapshot

A current snapshot of accounts, not a historical trend - this app doesn't keep a login history beyond each account's most recent login. Select a number to see which accounts it counts.

Storage Path Diagnostics

Shows exactly where the running server is reading/writing its data on disk right now - useful if something uploaded through Plesk's File Manager (narratives, cave maps, etc.) isn't showing up on the site, since that usually means a mismatch between where files were placed and where this app is actually looking. Shows folder paths and file names only, never file contents.


    


    

      
Email Diagnostics

      
"Forgot password" never reveals whether sending actually succeeded (so it can't be used to find out which emails are registered), so there's no way to tell from that form alone whether email is broken. Use this instead: "Check Configuration" reports what's set and tests the SMTP connection without sending anything; "Send Test Email" also sends a real email to your own account's address and reports the exact result.
